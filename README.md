# SHIFT GLASS — Vercel + Neon

Проект не использует SQLite, `better-sqlite3`, Python или нативные Node-модули. Это Vite + React + TypeScript и Vercel Functions с Neon Postgres.

## 1. Запуск на компьютере

Нужен Node.js LTS (рекомендуется Node 22 LTS). В режиме `npm run dev` приложение использует локальное сохранение в браузере для проверки интерфейса: Vite сам по себе не запускает Vercel Functions. Для реальной базы и серверного API используйте деплой на Vercel.

```bash
npm install
npm run dev
```

Для production-сборки:

```bash
npm run build
```

## 2. Создать GitHub-репозиторий

1. Создайте пустой репозиторий на GitHub, например `schedule`.
2. Распакуйте архив.
3. В папке проекта откройте терминал и выполните:

```bash
git init
git add .
git commit -m "Initial SHIFT GLASS app"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/schedule.git
git push -u origin main
```

## 3. Подключить Vercel

1. Войдите на vercel.com через GitHub.
2. Add New → Project → импортируйте `schedule`.
3. Framework Preset: Vite. Build Command: `npm run build`. Output Directory: `dist`.
4. Нажмите Deploy.

## 4. Создать Neon базу через Vercel

1. В проекте Vercel откройте Storage / Marketplace.
2. Выберите Neon Postgres и создайте базу.
3. Подключите её к проекту. Убедитесь, что Vercel добавил `DATABASE_URL` в Environment Variables.
4. Откройте Neon SQL Editor, вставьте весь файл `schema.sql` и выполните.
5. В Vercel → Settings → Environment Variables добавьте `ADMIN_PASSWORD` со своим новым секретным паролем. Секрет не добавлять в исходники и не отправлять в GitHub.
6. После добавления переменных сделайте Redeploy.

## Что уже есть

- Создание профиля сотрудника и сохранение его ID на устройстве.
- Локальный режим разработки без ошибки API: профиль и пожелания временно сохраняются в браузере, пока приложение запущено через Vite.
- Интервалы доступности на 7 дней, выходные, флаг +1 час, ограничения.
- Подсчёт часов и ориентировочной оплаты по ставке.
- Автоматическая отправка после заполнения недели (кнопка доступна для отправки/обновления).
- API для записи пожеланий в Neon.
- Менеджерский просмотр отправленных пожеланий.
- Ручные назначения по точкам и проверка пересечений сотрудников.
- Серверные API routes в `api/`.

## Важные ограничения этой первой deployable версии

- Telegram Mini App initData пока не подключён: профиль создаётся без Telegram-авторизации. Не используйте этот MVP как защищённую систему персональных данных до добавления Telegram auth.
- Вход менеджера сейчас проверяет пароль сервером, но полноценная сессия/авторизация последующих manager API ещё требует завершения. Не публикуйте URL панели как защищённый доступ.
- Telegram-уведомления, дедлайн с блокировкой изменений, напоминания и полноценное покрытие двух сотрудников Верхних Котлов-01 до 15:00 ещё не реализованы.
- Форма назначений пока хранит по одной строке на точку в день; для полноценной сменной сетки нужно добавить несколько интервалов на точку.
- В расчёте ставки используется локальный ввод сотрудника; это предварительная оценка, а не расчёт зарплаты.
